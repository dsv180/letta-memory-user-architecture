# Работа с секретами

Справочный файл. Читай, когда речь заходит об API-ключах, токенах, auth.json или настройке безопасности.

## Главное правило

**НИКАКИЕ секреты, API-ключи, токены не должны быть доступны агенту.** Ни для чтения, ни для передачи, ни для использования в командах.

## Что нельзя делать

- Читать `auth.json` или любые файлы конфигурации с ключами — **грубейшее нарушение**. Даже если нужна только структура (не значения) — сначала спросить пользователя, можно ли, или попросить его показать формат самому.
- Предлагать записывать API-ключи в переменные окружения, которые может прочитать агент (Bash tool).
- Смотреть, выводить, трогать файлы конфигурации с ключами.

## Почему system env — не вариант

**Windows system environment variables НЕ безопасны** — их может прочитать любой процесс на ПК и любой скрипт в браузере. Никогда не предлагать их для хранения API-ключей.

## `settings.json` env-блок Letta

Внутренние переменные процесса Letta (Node.js). Видны только процессу Letta Desktop, не системе и не браузеру. Это лучше, чем system env, но всё равно не идеально — ключ дублируется и живёт вне хранилища провайдеров.

## Если моду нужен API-ключ

Если мод требует API-ключ, но не умеет брать его из хранилища провайдеров Letta — это проблема архитектуры мода/харнеса, а не повод для костыля. Лучшее решение: пропатчить мод так, чтобы он читал credentials из хранилища Letta (не читая файл с секретами, а используя код самого харнеса), или отложить мод до обновления.
