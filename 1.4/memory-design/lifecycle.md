# Жизненный цикл памяти
Процедуры: как менять структуру памяти и как выпускать её версии.
Устройство памяти — в [[memory-design/architecture.md]].
Конкретика рабочего репозитория версий (URL, клон, бэкап, скрипты `tools/`) — в локальном справочнике `reference/lessons/memory-repo.md` (в публичный слепок не входит).

## Добавление файла
1. Определить слой: `system/`, `reference/`, `projects/`, `memory-design/`.
2. `reference/` — дописать ссылку в `lessons.md` или в раздел слоёв architecture.md.
3. `projects/` — запись в `projects/index.json` и `[[path]]`-ссылка в `projects/index.md`.
4. Проставить `version: 1.Х` внутри `description`.

## Удаление файла
1. Убедиться, что информация не дублируется.
2. Убрать ссылку из индекса (`lessons.md` / `index.json` / `index.md`).
3. Удалить файл.

## Обновление версии памяти (1.Х → 1.Ү)
Слепок — снимок структуры памяти; живая память остаётся в `$MEMORY_DIR`.
Новая версия — когда меняется **структура или правила**, а не содержимое проектов.

1. Бэкап всей папки `memory/`.
2. Проверить чистоту живой памяти: `git -C "$env:MEMORY_DIR" status --short` — пусто, иначе разобрать.
3. Привести слои к новой версии, сверить с целевой.
4. Скопировать в слепок четыре папки — `system`, `reference`, `projects`, `memory-design` — обязательно с `\*` у источника, иначе папка вложится подпапкой.
5. Поднять `version` в каждом `description` слепка.
6. Обезличить конвейером `tools/` (репозиторий публичный).
7. Гейт: `check-anonymized.py` → `exit 0`.
8. Коммит и push в ветку репозитория версий.
9. Переставить тег версии на новый коммит.

## Обезличивание (обязательный шаг выпуска)
Слепок публикуется в открытый репозиторий, поэтому персональные данные в него не попадают: имена, рабочие пути, реальные проекты, корпоративная специфика.
Обезличивание — воспроизводимый конвейер в самом репозитории (`tools/`), а не ручная правка: ручная слетает при следующей синхронизации.
Правила двухслойные: общий публичный слой + gitignored локальный (имена и организации каждой машины).
Инструменты и команды — в локальном справочнике (в публичный слепок не входит).
**Живая память НЕ обезличивается** — это память агента, а не публикация.

## Смена истории репозитория
`git filter-repo --replace-text` не годится, если в репозитории есть служебные файлы, где сами паттерны хранятся как данные (правила обезличивания): замены применяются ко всей истории и ломают такие файлы.
Способ — **сброс истории**: `git checkout --orphan` → один чистый коммит текущего дерева → force-push в основную ветку + переставить тег.
Обязателен бэкап клона (копия папки целиком) — старая история остаётся только там.
Специфика `filter-repo` на Windows — в [[reference/lessons/git-local.md]].

## Типовые ошибки
- Личное имя искать по корню слова, а не по целой форме: поиск по полной форме не поймает падежи.
- Копирование без `\*` у источника вкладывает папку подпапкой — [[reference/lessons/windows-guide.md]].
- Плейсхолдеры вида `<username>` / `<user>` — не персональные данные; гейт не должен на них срабатывать.
- `git add` с несуществующим путём не стейджит ничего — после коммита проверять `git status --short` и `git log --oneline -1` ([[reference/lessons/git-local.md]]).
