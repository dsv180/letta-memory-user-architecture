# Применение архитектуры к своей памяти
Как развернуть эту архитектуру у себя, ничего не потеряв. Разовая процедура: после неё память живёт по [[memory-design/lifecycle.md]].

## Что такое версия
Слепок — снимок структуры памяти, а не живая память:

    1.4/
    ├── memory-design/     — конституция: устройство и процедуры
    ├── reference/         — правила поведения, уроки, справочники
    ├── projects/          — инструкции, шаблон, примеры проектов
    ├── system/            — ядро: persona.md, human.md
    └── system-prompt/     — компактный system prompt

## Главное правило: слияние, а не перезапись
НЕ копируй слепок поверх своей памяти. Твоя живая память уникальна: в ней твои проекты, твои данные пользователя, твои уроки. Слепок даёт структуру и общие правила, но не заменяет личное.

## Что можно брать
- `memory-design/` — целиком: устройство (`architecture.md`), сопровождение (`lifecycle.md`), миграция (этот файл).
- `reference/core-rules.md`, `reference/lessons.md`, `reference/lessons/*` — правила и уроки. Переноси то, чего у тебя нет; свои уроки не удаляй.
- `projects/PROJECTS.md`, `projects/_template.json`, `projects/index.md` — инструкции, шаблон нового проекта и схема связей.

## Что НЕ копировать
- `system/persona.md`, `system/human.md` — личность и данные пользователя у каждого свои.
- `projects/index.json` — твой манифест проектов; в слепке он пуст.
- `projects/_examples/` — примеры структуры, а не твои проекты.
- `system-prompt/system-prompt.txt` — применять только осознанно (процедура — в `reference/lessons/system-prompt-updates.md`).

## Порядок применения
1. Сделай снимок своей памяти (git-коммит или копию папки) — чтобы был откат.
2. Приведи структуру к слоям: `system/`, `memory-design/`, `reference/`, `projects/`.
3. Перенеси общие правила и уроки, не затирая свои.
4. Приведи `projects/` к схеме: `PROJECTS.md` + `index.json` + `index.md` + `_template.json`; каждый проект — к фиксированному набору файлов (`config.md`, `notes.md`, `tasks.md` + опциональные `skills.md`, `glossary.md`, `lessons.md`). Свои проекты не удаляй — только приведи к схеме.
5. Frontmatter каждого `.md`: `description` обязателен, `version` — внутри `description`, в кавычках.
6. Проверь `[[path]]`-ссылки и обнови `projects/index.json`.

## После внедрения
Память живёт по [[memory-design/lifecycle.md]]: добавление и удаление файлов, обновление своей версии, выпуск слепка.

## Публикация своей памяти (обезличивание)
Если публикуешь свою память в открытый репозиторий — обезличь её до коммита, иначе личные данные уйдут в публичную историю навсегда. Конвейер лежит в репозитории версий, в `tools/`:
1. Скопируй `tools/anonymize.local.example.json` → `tools/anonymize.local.json` и впиши свои имена, организации и специфичные диски (файл в `.gitignore`).
2. `python tools/anonymize.py --dry-run` — план.
3. `python tools/anonymize.py` — применить.
4. `python tools/check-anonymized.py` — гейт: `exit 1` означает найденные данные.
5. `git config core.hooksPath tools/hooks` — гейт будет срабатывать перед каждым push.

Пути в правилах не зашиты: берутся из переменных окружения машины (`$MEMORY_DIR`, `~`, `$LETTA_LOCAL_BACKEND_DIR`), поэтому конвейер переносим между машинами и ОС. Общий слой правил публикуется, локальный — нет.
