# Обновление system prompt при апдейте ЛД
## Зачем это нужно
У агента system prompt заменён на компактный (см. `system-prompt/` в репо памяти). При обновлении ЛД базовый промпт в новой версии может измениться — добавиться новые секции, измениться формулировки. Наш кастомный промпт этих изменений не подхватит автоматически.
Харнес Letta Code умеет auto-heal для агентов с тегом `origin:letta-code`, но лечит только скелетные секции, которые распознаёт как «свои». Если в новой версии появится принципиально новая секция — она не добавится.
Результат: агент молча теряет новые возможности. Чтобы это поймать — нужна ручная проверка.
## Когда проверять
- После каждого апдейта ЛД (кнопка «обновить» в интерфейсе).
- После ручной переустановки.
- Раз в месяц — если апдейты не приходили.
## Процедура
### 1. Создать тестового агента
Тестовый агент создастся с новым базовым промптом из свежей версии харнеса. Это единственный надёжный способ увидеть, что изменилось.
Способ А — через UI:
- Открыть профиль-селектор в ЛД.
- Создать нового агента с пресетом `letta-code`.
- Дать любое имя, например `prompt-check-temp`.
Способ Б — через CLI:
```
letta --new-agent --personality letta-code
```
### 2. Прочитать промпт тестового агента
```
npx tsx "<SKILL_DIR>/update-agent-settings.ts" --target agent --agent-id "<test-agent-id>" --show
```
В ответе — JSON с полем `system`. Это и есть текущий базовый промпт. Скопировать в файл для сравнения:
```
$test = <вывод выше>
Set-Content -LiteralPath "<CWD агента>\.temp\prompt-from-new-ld.txt" -Value $test.system -Encoding utf8
```
### 3. Сравнить с нашим
Наш промпт: `<клон репо памяти>\system-prompt\system-prompt.txt`
Прямое сравнение покажет огромную дельту — наш промпт сознательно сокращён. Правильнее — выделить секции.
Секции нового промпта:
```
Select-String -Path "<CWD агента>\.temp\prompt-from-new-ld.txt" -Pattern "^# " | Select-Object -ExpandProperty Line
```
Секции нашего промпта:
```
Select-String -Path "<клон репо памяти>\system-prompt\system-prompt.txt" -Pattern "^# " | Select-Object -ExpandProperty Line
```
Дельта в заголовках — то, что требует внимания.
### 4. Решить, что делать
Для каждой новой секции базового промпта:
- Нужна агенту — если это инструкция к новому инструменту или изменившейся механике харнеса, добавить.
- Не нужна — если это философия, маркетинг или дубль существующего, пропустить.
Если решили добавить — вписать в стиле остальных секций: короткие буллеты, без воды, на английском.
### 5. Применить патч
1. Отредактировать `system-prompt/system-prompt.txt` — добавить новую секцию.
2. Dry-run:
```
npx tsx "<SKILL_DIR>/update-agent-settings.ts" --target agent --agent-id "$env:AGENT_ID" --system-file "<путь>" --dry-run
```
3. Проверить вывод — только поле `system`.
4. Применить:
```
npx tsx "<SKILL_DIR>/update-agent-settings.ts" --target agent --agent-id "$env:AGENT_ID" --system-file "<путь>" --confirm-system-replacement
```
5. Проверить размер поля `system` в JSON агента.
6. Сказать пользователю: «готово, сделай /reload».
7. Открыть новый диалог, убедиться, что промпт применился.
### 6. Зафиксировать в репо
```
git -C "<клон репо памяти>" add system-prompt/system-prompt.txt
git -C "<клон репо памяти>" commit -m "system-prompt: патч после апдейта ЛД до <версия>"
git -C "<клон репо памяти>" push origin master
```
### 7. Удалить тестового агента
Через UI: найти `prompt-check-temp` в списке, удалить.
## Что важно помнить
- Не переписывать промпт целиком. Только добавить дельту.
- Проверять dry-run перед применением. Если патч задел `llm_config`, `tags`, `model_settings` — стоп, разбираться.
- `/reload` после применения. Без него промпт не подхватится в активных диалогах.
- Старые диалоги остаются со старым промптом. Проверять эффект только в новом диалоге.
- Версия промпта меняется в git через коммиты. Отдельная нумерация не нужна, git хранит историю.
