# Субагенты — справочник
Подробности к краткому блоку ядра [[system/subagents.md]]. Устройство памяти и место субагентов в ней — [[memory-design/architecture.md]]; правила поведения и границы — [[reference/core-rules.md]]. Источник фактов — документация Letta (`docs.letta.com/configuration/subagents`, `concepts/memfs`).

## Встроенные субагенты
Семь типов. Харнес сам подбирает модель (`auto`/`auto-fast`); можно переопределить промптом.

| Субагент | Назначение | Модель | Доступ |
|---|---|---|---|
| `fork` | Форк текущего диалога с полным контекстом и инструментами | `inherit` | чтение/запись |
| `general-purpose` | Полная реализация: исследование, план, изменения | `auto` | чтение/запись |
| `history-analyzer` | Перенос истории (Claude Code / Codex) в память | `auto` | чтение/запись |
| `init` | Быстрая инициализация памяти по проекту | `auto-fast` | чтение/запись |
| `memory` | Реорганизация памяти: разбиение, слияние дублей, иерархия | `auto` | чтение/запись |
| `recall` | Поиск по истории бесед | `auto-fast` | только чтение |
| `reflection` | Фоновая (sleep-time) консолидация памяти | `auto` | чтение/запись |

## Как это работает
- **Запуск.** Основной агент запускает субагента инструментом делегирования; субагент работает автономно со своим системным промптом, инструментами и моделью.
- **Возврат.** В контекст основного агента попадает **только финальное сообщение** субагента — промежуточные шаги и tool-calls остаются вне (на этом архитектура и держит ядро компактным).
- **Фон.** В фоновом режиме основной агент продолжает работу, а по завершении в диалог внедряется уведомление с результатом.
- **Повторное использование.** Встроенные субагенты создаются заново на каждый вызов. Развернуть можно и произвольного агента по `agent_id` (со своей памятью и личностью) — оба агента должны быть в одном проекте Letta; если ID забыт, поможет встроенный скилл `finding-agents`.
- **Память.** Пишущие в память субагенты (`dreaming`, `memory doctor`) используют git-worktree и коммитят к себе — чтобы обновлять память, не блокируя основной агент; слияние в память делает основной агент после проверки диффа.

## Кастомные субагенты
Markdown-файл с YAML-frontmatter в `.letta/agents/` (проектный) или `~/.letta/agents/` (глобальный). Проектный переопределяет глобальный с тем же именем; оба переопределяют встроенный.

| Поле | Обязательно | Описание |
|---|---|---|
| `name` | да | Уникальное имя (строчные, дефисы; начинается с буквы) |
| `description` | да | Когда применять — видно в инструменте делегирования и `/subagents` |
| `tools` | нет | Инструменты через запятую или `all` (по умолчанию `all`) |
| `model` | нет | Модель (напр. `sonnet`); по умолчанию наследуется от основного агента |
| `memoryBlocks` | нет | Блоки памяти: список, `all`, `none` (по умолчанию `all`) |
| `skills` | нет | Скиллы для авто-загрузки, через запятую |

Тело файла (после frontmatter) становится системным промптом субагента. Пример:

```markdown
---
name: security-reviewer
description: Проверяет код на типовые уязвимости и предлагает правки
tools: Glob, Grep, Read
---
Ты — ревьюер безопасности. Ищи SQL-инъекции, XSS, слабую валидацию ввода и зашитые секреты.
Отвечай списком находок: критичность, путь и номер строки, рекомендуемая правка.
```

## Протокол «предложил → проверил → смержил»
Для любого изменения памяти субагентом:
1. **Предложил** — субагент работает в изолированном worktree, коммитит изменения в него и возвращает краткое сообщение с итогом.
2. **Проверил** — основной агент читает дифф (что и куда записано), сверяет с [[memory-design/architecture.md]] («Что куда») и проверяет, что субагент не тронул ядро.
3. **Смержил** — основной агент вливает изменения в память и коммитит. Ядро (`system/`) субагент не правит — только основной агент ([[reference/core-rules.md]]).

Правило делегирования по умолчанию — в ядре: объёмное, побочное или параллелизуемое — субагенту; мелкое — самому.

## Субагенты и проект
Проектные субагенты — определения (Markdown с YAML-frontmatter) лежат на диске проекта:
    <physical_path>\.letta\agents\<имя>.md
Это файловая система проекта, не MemFS. Глобальные определения — `~/.letta/agents/`.
Приоритет имён: проектное перекрывает глобальное, оба — встроенный субагент с тем же именем. Проектные доступны, когда CWD диалога = папка проекта.

В MemFS кладётся не само определение, а отметка: **секция `subagents:` в `config.md`** — какие проектные субагенты есть и зачем. Поля определений — в таблице «Кастомные субагенты» выше.
