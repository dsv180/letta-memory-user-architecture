# Letta Memory Architecture

Архитектура памяти агента на Letta Code: как память устроена, по каким правилам живёт и как развернуть её у себя. Репозиторий хранит **версии архитектуры** — обезличенные слепки структуры памяти, а не живую память агента.

В рабочем дереве всегда лежит одна актуальная версия. Папок старых версий нет: история — в тегах, Releases и [`CHANGELOG.md`](CHANGELOG.md).

**Актуальная версия: v1.5** — плоская структура, версионирование тегами.

## С чего начать

| Кто ты | Что читать |
|---|---|
| Агент: развернуть или обновить память по этой архитектуре | сначала `memory-design/architecture.md` (устройство), затем **`memory-design/migration.md`** (процедура применения) |
| Владелец: выпустить новую версию архитектуры | `memory-design/lifecycle.md`; инструменты — в `tools/` |
| Хочешь просто понять, как устроена память | `memory-design/architecture.md`, `reference/core-rules.md` |

## Если ты агент
Тебя направили на этот репозиторий — значит, у тебя есть задача развернуть или обновить память по этой архитектуре.

1. Прочитай `memory-design/architecture.md` — устройство памяти: слои, файлы, соглашения.
2. Открой **`memory-design/migration.md`** — это процедура применения. Действуй по ней.
3. Главное правило: **слияние, а не перезапись**. Свои проекты, `system/persona.md`, `system/human.md` и `projects/index.json` не трогай.

Всё в репозитории обезличено: реальных имён, путей и проектов здесь нет, есть только структура и общие правила.

    │   ├── persona.md         — кто агент: ценности и подход к работе
    │   └── human.md           — кто пользователь: язык, предпочтения
    │
    ├── reference/             — правила поведения и уроки

    │   └── lessons/           — уроки, по одному файлу на тему
    │
    ├── projects/              — рабочие контексты, каждый проект изолирован
    │   ├── PROJECTS.md        — инструкции по работе с проектами
    │   ├── index.json         — манифест проектов и статусы (в слепке пуст)
    │   ├── index.md           — связи между файлами проектов
    │   ├── _template.json     — шаблон нового проекта
    │   └── _examples/         — примеры структуры проекта
    │
    ├── system-prompt/         — компактный system prompt агента
    │   └── system-prompt.txt
    │
    └── tools/                 — инструменты репозитория (не часть версии)
        ├── anonymize.py            — обезличивание слепка
        ├── anonymize.rules.json    — общий (публикуемый) слой правил обезличивания
        ├── anonymize.local.example.json — образец локального слоя (имена, организации машины)

Служебные файлы: `.gitattributes` (переводы строк — LF) и `.gitignore`. Локальный `tools/anonymize.local.json` не публикуется — он у каждой машины свой.

## Как устроена память
- **Слои памяти.** `system/` — ядро, всегда в контексте; `memory-design/` — конституция; `reference/` — правила поведения, уроки, справочники; `projects/` — рабочие контексты.
- **`memory-design/` — самодостаточное ядро.** Устройство (`architecture.md`) и все процедуры (`lifecycle.md` — сопровождение, `migration.md` — внедрение) лежат вместе. Взял папку — можно начинать, не имея ни уроков, ни проектов; переделки `reference/` и `projects/` ядро не задевают.
- **Уроки — не один файл.** `reference/lessons.md` — только точка входа и индекс. Сами уроки лежат отдельными файлами в `reference/lessons/`, по одному на тему. Так урок можно перечитать точечно, не вываливая в контекст всё. Общие уроки живут здесь; специфичные для проекта — в `project-rules/` внутри проекта.
- **Проекты — изолированные контексты.** У каждого свои инструкции, данные и скиллы. Внутри проекта фиксированный набор: `config.md`, `notes.md`, `tasks.md` (+ опционально `skills.md`, `glossary.md`, `project-rules.md` и папка `project-rules/`). Общее для всех проектов: `PROJECTS.md` (инструкции), `index.json` (манифест и статус), `index.md` (связи), `_template.json` (шаблон нового проекта). Статус проекта хранится только в `index.json`.
- **Короткие `persona.md` и `human.md`.** В `system/` лежит только ядро — то, что должно быть в контексте всегда. Полные профили остаются у владельца. В слепке эти два файла ещё и обезличены.
- **Frontmatter.** У каждого файла памяти есть `description` (обязателен); версия архитектуры указывается внутри `description`, отдельного поля `version` нет.

## Версии
Версия — это **тег** (`v1.5`) и **Release** на GitHub, а не папка. В рабочем дереве версия одна; выпущенные теги неизменяемы, старые релизы остаются на своих коммитах со своей структурой. Нумерация внутри файлов (`version: 1.5` в `description`) совпадает с тегом.

Процедура выпуска — `memory-design/lifecycle.md`; коротко: привести слои к новой версии → `tools/bump-version.py` → скопировать слои в репозиторий → обезличить → гейт → `CHANGELOG.md` → коммит и push → новый тег и Release.

## Обезличивание
Слепок публикуется в открытый репозиторий, поэтому персональные данные в него не попадают: имена, рабочие пути, реальные проекты, корпоративная специфика.

Это воспроизводимый конвейер (`tools/`), а не ручная правка — ручная слетит при следующей синхронизации. Правила двухслойные: общий публикуемый слой + локальный (в `.gitignore`), где хранится конкретика каждой машины. Перед каждым push срабатывает гейт `check-anonymized.py`.
