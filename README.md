# Letta Memory Architecture
Архитектура памяти агентов на Letta Code: структура, правила, уроки. Репозиторий хранит **версии архитектуры** — слепки структуры памяти, а не живую память. В рабочем дереве всегда лежит одна актуальная версия; история версий — в тегах, [Releases](https://github.com/<логин GitHub>/letta-memory-user-architecture/releases) и [`CHANGELOG.md`](CHANGELOG.md).

## Если ты агент
Тебя направили на этот репозиторий — значит, у тебя есть задача развернуть или обновить память по этой архитектуре.

1. Прочитай `memory-design/architecture.md` — устройство памяти: слои, правила, соглашения.
2. Открой **`memory-design/migration.md`** — это процедура применения. Действуй по ней.
3. Главное правило: **слияние, а не перезапись**. Свои проекты, `system/persona.md`, `system/human.md` и `projects/index.json` не трогай.

Всё в репозитории обезличено: реальных имён, путей и проектов здесь нет, есть только структура и общие правила.

## Суть реализации
- **Слои памяти.** `system/` — ядро, всегда в контексте; `memory-design/` — конституция; `reference/` — правила поведения, уроки, справочники; `projects/` — рабочие контексты.
- **`memory-design/` — самодостаточное ядро.** Устройство (`architecture.md`) и все процедуры (`lifecycle.md` — сопровождение, `migration.md` — внедрение) лежат вместе. Взял папку — можно начинать, не имея ни уроков, ни проектов; переделки `reference/` и `projects/` ядро не задевают.
- **Уроки — не один файл.** `reference/lessons.md` — только точка входа и индекс. Сами уроки лежат отдельными файлами в `reference/lessons/`, по одному на тему. Так урок можно перечитать точечно, не вываливая в контекст всё. Общие уроки живут здесь; проектные — в `project-rules/` своего проекта.
- **Проекты — изолированные контексты.** У каждого свои инструкции, данные и скиллы. Внутри проекта фиксированный набор: `config.md`, `notes.md`, `tasks.md` (+ опционально `skills.md`, `glossary.md`, `project-rules.md` и папка `project-rules/`). Общее для всех: `PROJECTS.md` (инструкции), `index.json` (манифест и статус), `index.md` (связи), `_template.json` (шаблон нового проекта). Статус проекта хранится только в `index.json`.
- **Короткие `persona.md` и `human.md`.** В `system/` лежит только ядро — то, что должно быть в контексте всегда. Полные профили остаются у владельца. В слепке эти два файла ещё и обезличены.
- **Frontmatter.** У каждого файла памяти есть `description` (обязателен); версия архитектуры указывается внутри `description`, отдельного поля `version` нет.
- **Обезличенный слепок.** Каждая опубликованная версия прогнана через конвейер `tools/`: машинные пути заменены на канон Letta (`$MEMORY_DIR`, `~`, …), личное — вычищено. Перед каждым push срабатывает гейт.

## Структура
    .
    ├── memory-design/     — ядро: architecture.md (устройство), lifecycle.md (сопровождение), migration.md (внедрение)
    ├── projects/          — инструкции, манифест, связи, шаблон, примеры проектов
    ├── reference/         — core-rules.md, lessons.md и lessons/ (уроки и справочники)
    ├── system/            — ядро: persona.md, human.md
    ├── system-prompt/     — компактный system prompt
    └── tools/             — конвейер обезличивания и генераторы (инструмент репозитория, не часть версии)

## Версии
Версия — это **тег** (`v1.5`) и **Release** на GitHub, а не папка. В рабочем дереве версия одна: папок старых версий нет, их история — в тегах и релизах. Нумерация внутри файлов (`version: 1.5` в `description`) совпадает с тегом.

## Дальше

- **Выпустить новую версию архитектуры** (владельцу репозитория) → [`memory-design/lifecycle.md`](memory-design/lifecycle.md); инструменты — в `tools/`.
