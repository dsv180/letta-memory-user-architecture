# Применение архитектуры к своей памяти
Как развернуть эту архитектуру у себя, ничего не потеряв. Разовая процедура: после неё память живёт по [[memory-design/lifecycle.md]].

## Что такое версия
Слепок — снимок структуры памяти, а не живая память; версия репозитория — тег на коммите, папки версии нет (понятия — [[memory-design/lifecycle.md]], раздел «Выпуск новой версии»). Слои слепка:

    memory-design/     — конституция: устройство и процедуры
    reference/         — правила поведения, служебное слоя project/, индексы
    lessons/           — уроки и справочники по темам
    project/           — папки проектов
    system/            — ядро: persona.md, human.md, active-work.md
    system-prompt/     — компактный system prompt

Версия своей живой памяти хранится в `memory-design/manifest.json` (`memory_version`), там же — граница «канон/личное». Переход своей памяти между версиями — по дельте `memory-design/deltas/<версия>.md` ([[memory-design/lifecycle.md]]). Внедрение чужой или старой памяти дельту не применяет: разбор идёт по содержимому, версия источника не спрашивается.

## Главное правило: слияние, а не перезапись
НЕ копируй слепок поверх своей памяти. Твоя живая память уникальна: в ней твои проекты, твои данные пользователя, твои уроки. Слепок даёт структуру и общие правила, но не заменяет личное.

## Шаблоны и эталоны — образец формы, а не данные
`memory-design/templates/*`, `reference/_template.json`, `project/_examples/*` — образцы того, как выглядят реальные файлы (переменные `{{...}}`, плейсхолдеры `<...>`, примерные записи). Переносятся структура и инструкции, а содержимое ты заполняешь своими данными. Скопировать образец «как есть» — значит получить память с чужими плейсхолдерами вместо своих данных.

## Что куда при слиянии
Переносимое знание раскладывается по слоям ([[memory-design/architecture.md]], раздел «Что куда»): общие правила — в `reference/`/`lessons/`, специфика — в `project/<name>/`. Свои правила, которых нет в каноне, не удаляй — держи в своём слое правил или в `project-rules/`.

## Разбор своих уроков
У потребителя после обновления остаются накопленные уроки трёх видов: нюанс одного проекта, устаревшее/расформированное (структура изменилась, правила новые), совершенно новое и не проектное.
Сопоставляй уроки **по содержимому**, а не по имени файла или версии источника: версия не спрашивается, цель всегда — текущий канон (работает и для недо-доделанной старой версии). Карта «версия → версия» не масштабируется.
Каждый урок проверяй на дублирование в каноне; решение — одно из четырёх:
1. **в канон** — общее, полезно всем;
2. **в `project-rules/`** — нюанс одного проекта;
3. **удалить** — устарело или дублирует канон;
4. **новый урок-дополнение** — локальное дополнение установленного канона, не общий слой.

## Что можно брать
- `memory-design/` — целиком: устройство (`architecture.md`), сопровождение (`lifecycle.md`), миграция (этот файл), публикация (`publication.md`), эталоны ядра (`templates/persona.md`, `templates/human.md`).
- `reference/core-rules.md`, `reference/lessons.md`, `lessons/*` — правила и уроки. Переноси то, чего у тебя нет; свои уроки не удаляй.
- `reference/PROJECTS.md`, `reference/_template.json`, `reference/index.md` — инструкции, шаблон нового проекта и схема связей.

## Что НЕ копировать
- `system/persona.md`, `system/human.md` — личность и данные пользователя у каждого свои.
- `reference/index.json` — твой манифест проектов; в слепке — полный пример записи.
- `project/_examples/` — примеры структуры, а не твои проекты.
- `system-prompt/system-prompt.txt` — применять только осознанно (процедура — в `lessons/system-prompt-updates.md`).

## Preflight окружения
До правок проверь инструменты — иначе массовые операции молча ломают файлы.
- **Кодировка.** Запись UTF-8 **без BOM**: BOM в начале файла ломает frontmatter и первую ссылку.
- **`git mv`.** Не раскрывает маску (`git mv memory/*.md dst/` не сработает) и при существующем приёмнике вкладывает источник внутрь него — переименовывай по одному файлу и проверяй результат.
- **Версии.** Массовая правка версии — по всему тексту файла, а не только в строке `description`.
- **Переносы строк.** На Windows файлы памяти — CRLF: многострочный `old_string` по ним не находится, правь построчно или скриптом с автоопределением разделителя ([[lessons/memory.md]]).
- **Откат.** Снимок памяти (п.1 порядка) сделан — без него работу не начинать.

## Порядок применения
1. Сделай снимок своей памяти (git-коммит или копию папки) — чтобы был откат.
2. Приведи структуру к слоям: `system/`, `memory-design/`, `reference/`, `project/`.
3. Перенеси общие правила и уроки, не затирая свои.
4. Держи служебное слоя (`PROJECTS.md`, `index.json`, `index.md`, `_template.json`) в `reference/`, в `project/` — только папки проектов; каждый проект — к фиксированному набору файлов (`config.md`, `notes.md`, `tasks.md` + опциональные `skills.md`, `glossary.md`, `project-rules.md` и папка `project-rules/`). Свои проекты не удаляй — только приведи к схеме.
5. Frontmatter каждого `.md`: `description` обязателен, `version` — внутри `description`, в кавычках.
6. Проверь `[[path]]`-ссылки и обнови `reference/index.json`.
7. Ядро (`system/persona.md`, `system/human.md`) заполни своими данными: возьми эталон из `memory-design/templates/` и подставь вместо переменных свои значения — `{{AGENT_NAME}}`, `{{AGENT_STRICT_NAME}}`, `{{USER_NAME}}`, `{{USER_LANGUAGE}}`. Личные данные в канон не попадают — они живут только в живой памяти.

## Чек-лист «миграция завершена»
Формальный признак завершённости — прогон валидатора (#7) даёт `exit 0` ([[reference/MEMORY-HEALTH.md]]). Полу-мигрированного состояния быть не должно: часть путей старая, часть новая — это ещё не завершено.
- [ ] У каждого `.md` валидный frontmatter: `description` есть, версия — внутри него.
- [ ] Все `[[...]]` — полные пути, не битые.
- [ ] Файлы на своих слоях; в корне памяти — только разрешённые папки.
- [ ] В `project/` — только папки проектов, каждая с `config.md`, `notes.md`, `tasks.md`.
- [ ] Служебное слоя `project/` перенесено в `reference/`.
- [ ] `manifest.json` заполнен: `memory_version` и границы `canon`/`local`.
- [ ] Ядро (`system/persona.md`, `system/human.md`) — свои данные, без плейсхолдеров `{{...}}`.
- [ ] Индексы (`lessons.md`, `index.json`, `index.md`) согласованы с содержимым.
- [ ] Старых путей и старой схемы не осталось ни в одном файле.

## После внедрения
Память живёт по [[memory-design/lifecycle.md]]: добавление и удаление файлов, обновление своей версии, выпуск слепка. Публикация обезличенного слепка — в [[memory-design/publication.md]].
