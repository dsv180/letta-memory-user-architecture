# Публикация памяти
Как выложить свою память открытым слепком, не выпустив личные данные в публичную историю. Внедрение архитектуры в свою память — в [[memory-design/migration.md]]; выпуск версии — в [[memory-design/lifecycle.md]] (публикация — его финальный шаг).
Слепок — снимок структуры памяти, а не живая память; версия — тег на коммите репозитория.

## Обезличивание (обязательный шаг выпуска)
Слепок публикуется в открытый репозиторий, поэтому персональные данные в него не попадают: имена, рабочие пути, реальные проекты, корпоративная специфика.
Обезличивание — воспроизводимый конвейер в самом репозитории (`tools/`), а не ручная правка: ручная слетает при следующей синхронизации.
Правила двухслойные: общий публичный слой + gitignored локальный (имена и организации каждой машины), поэтому конвейер переносим между машинами и ОС.
**Живая память НЕ обезличивается** — это память агента, а не публикация.

## Ядро подменяется целиком
`system/persona.md` и `system/human.md` — личное (см. `manifest.json`, `local`), поэтому как есть в слепок не идут. Строковые замены в них не делаются: конвейер **заменяет эти файлы целиком** содержимым эталонов `memory-design/templates/persona.md` и `memory-design/templates/human.md` (эталоны — канон, в слепке публикуются как есть, с переменными `{{...}}`). Тот же приём, что `projects.index_template` в правилах обезличивания.
Причина: строковая замена имён хрупка (падежи, латиница↔кириллица, `forbidden_patterns` знает одну форму) и даёт нечитаемый текст; подмена файла целиком от персоналий не зависит.

## Конвейер (`tools/` в репозитории версий)
1. `tools/anonymize.local.example.json` → `tools/anonymize.local.json`: свои имена, организации, специфичные диски (файл в `.gitignore`).
2. `python tools/anonymize.py --dry-run` — план.
3. `python tools/anonymize.py` — применить.
4. `python tools/check-anonymized.py` — гейт: `exit 1` означает найденные данные.
5. `git config core.hooksPath tools/hooks` — гейт будет срабатывать перед каждым push.

Пути в правилах не зашиты: берутся из переменных окружения машины (`$MEMORY_DIR`, `~`, `$LETTA_LOCAL_BACKEND_DIR`). Общий слой правил публикуется, локальный — нет.

## Границы публикуемого
- **Ссылки.** Публикуемый файл не должен ссылаться `[[...]]` на непубликуемый: в слепке такая ссылка ведёт в никуда. Такую ссылку писать обычным текстом с пометкой «в публичный слепок не входит».
- **Что не попадает в слепок.** Служебное git (`.git`), рабочие `.temp`, `profile.png`, `skills/` (специфичны для агента), `system-prompt/` (в версии уже лежит готовый промпт); из `project/` — только `_examples/`. Точный список локальных файлов задаёт конвейер (секция `local_files` в общих правилах).

## Типовые ошибки обезличивания
- Личное имя искать по корню слова, а не по целой форме: поиск по полной форме не поймает падежи.
- Правило обезличивания проверять на реальной строке: лишний символ в шаблоне (например, `_` в конце пути) делает правило «мёртвым», и оно молча не срабатывает. Единственная страховка — гейт.
- Личные идентификаторы машины (логин ОС, личный e-mail, локальный псевдоним агента вида `agent-local-…@example.com`, регион, внутренние хосты, названия организаций) закрываются в локальном слое правил. Чего нет в правилах — гейт не поймает, и утечка уйдёт в публичную историю навсегда. Надёжнее не полагаться на правило: в самом публикуемом файле писать пример идентификатора плейсхолдером (`<agent-local-id>@example.com`, `<user>@…`) — тогда ловить нечего.
- Публикуемые файлы-индексы (`reference/PROJECTS.md`, `reference/index.json`) не должны содержать имена реальных проектов — только примеры и плейсхолдеры вида `<проект>`.
- Плейсхолдеры вида `<username>` / `<user>` — не персональные данные; гейт не должен на них срабатывать.
- Абсолютный URL на GitHub (`github.com/<логин>/...`) в публикуемом файле: обезличиватель заменит логин на плейсхолдер, и ссылка сломается молча — гейт такое не ловит, если плейсхолдер уже подставлен. В публичных файлах — только относительные ссылки.
- Личные имена в тексте писать так, чтобы после обезличивания фраза читалась: замена имени на обезличенную форму даёт корявое «Меня зовут пользователь». Проверять формулировку на реальной строке — как и сами правила замены.
- `forbidden_patterns` должны совпадать с формой слова в файлах: паттерн латиницей не поймает кириллическое написание (и наоборот) — гейт остаётся зелёным, а слово уходит в публичную историю.
