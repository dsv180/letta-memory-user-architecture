# Дельта 1.6 → 1.7
Переход **своей** живой памяти с версии 1.6 на 1.7. Внедрение чужой или старой памяти эту дельту не применяет — там работа по содержимому ([[memory-design/migration.md]]).
Поля `version` в этом файле нет намеренно: версия дельты — в имени файла, иначе механический подъём версии переписал бы историческое значение.

## Как применять
1. Убедиться, что `memory_version` в [[memory-design/manifest.json]] = `1.6`.
2. Пройти изменения ниже по разделам; личное (`project/`, `system/persona.md`, `system/human.md`) не трогать.
3. Поднять `version` в `description` файлов: `tools/bump-version.py 1.6 1.7 --root "$env:MEMORY_DIR"`.
4. Выставить `memory_version`: `1.7` в [[memory-design/manifest.json]].

## Структура
- `memory-design/deltas/` — новый подкаталог: дельты переходов между версиями (этот механизм).
- `memory-design/manifest.json` — новый файл: версия живой памяти и граница «канон/личное».
- `memory-design/templates/` — новый подкаталог: эталоны ядра (`persona.md`, `human.md`) с переменными `{{...}}`.
- `system/subagents.md` — новый блок ядра: что такое субагент и когда делегировать (всегда в контексте).
- `reference/MEMORY-HEALTH.md` — новый файл метрик здоровья памяти.
- `reference/SUBAGENTS.md` — новый справочник по субагентам.

## Правила
- **Ссылки** (`#3`): `[[...]]` — только полный путь от корня памяти; короткие запрещены; поиск коротких и битых — в валидаторе ([[reference/MEMORY-HEALTH.md]]).
- **Скиллы** (`#8`, `#27`): только `$MEMORY_DIR/skills/`; список допустимых папок верхнего уровня закреплён; правило «урок → скилл».
- **Границы слоёв** (`#5`): правило «что куда» + критерий своих правил вне канона.
- **Активный проект** (`#4`): якорь — файл `system/active-work.md`; блок `current_project` из канона убран.
- **Форма записи знания** (`#31`): общие требования к форме (содержание, форма, порядок, размер) для всех слоёв; даты вида `(дд.мм.гггг)` и атрибуции авторства из уроков, ядра, справочников и проектного слоя убраны. Исключение — файлы-хроники (`journal.md`, `tasks.md`): в них дата и ход работ уместны.
- **Внедрение ≠ публикация** (`#11`): разделение процедур на внедрение и публикацию.
- **Шаблонизация ядра** (`#30`): `persona.md`/`human.md` — эталон с переменными (`memory-design/templates/`) в каноне, персоналии только в живой памяти; при публикации файлы ядра подменяются эталоном целиком.
- **Разбор накопленных уроков** (`#29`): при внедрении — по содержимому, не по версии источника.
- **Конфликт имён копий на диске** (`#10`): при занятом имени, которое не наша копия, — спросить владельца, не перезаписывать.
- **Рантайм мода в `state/`** (`#13`): состояние модов — в `$MEMORY_DIR/state/`, папка исключается из git через `.git/info/exclude`.
